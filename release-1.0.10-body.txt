The 1.x series is named Polyglot, and the three products carry the name.

Why the name is in the products and not only in a document. The roadmap has always said that the only thing moving the minor number is a new language, six of them across one abstraction layer with the same look and feel in each. The series name says that out loud, so a person reading a Marketplace page sees what kind of thing this is, and a person reading 1.2 knows how far along the pathway the build is. The two shared libraries deliberately do not take the name: @projectrevivesolutions/complexity and @projectrevivesolutions/witness are package identifiers that other code imports by name, and renaming them would break every import to decorate a string nobody reads.

Where it lands. The Marketplace titles (displayName) become MikeVan's AI Development Toolkit - Polyglot, DeepTest - Polyglot, and UntangleIt - Polyglot, with no version, because displayName never carried one. The side panel headers become DeepTest - Polyglot 1.0.10 and UntangleIt - Polyglot 1.0.10, keeping the version exactly where it already was. Those headers are stamped into package.json by each tree's esbuild step rather than written by hand, because VS Code puts the container title in the panel header when a container holds one view and neither title can change at run time. The three README titles follow. The roadmap names both series and explains the 1.x one; 2.x is named Intellectus there and nothing more is said about it.

One deletion. release.ps1 carried a regex rewriting UntangleIt's view name with the version. The build has stamped that field, along with the container title and the contextual title, since those two lines were added, so the regex was already dead code touching one of three fields. It also matched on the literal name, so the rename would have stopped it matching without any error. Deleting it is the correct fix rather than teaching it the new pattern.
