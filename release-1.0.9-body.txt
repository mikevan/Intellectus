Witness leaves DeepTest and becomes its own library, @projectrevivesolutions/witness, the second library both extensions bundle. Nothing measured changes: node-mocha and react-playwright-ct give the 1.0.8 numbers to the line.

Why now. Witness was born inside DeepTest (1.0.6) so it could be proven on the ports before anything depended on it, and the plan had it moving out when UntangleIt first needed it. That was moved up: a shared language between two tools has to be a library both import, not code one of them happens to hold, and UntangleIt's behaviour gate is the next work.

What moved. src/witness/instrument.ts and hook.ts, a copy of the shared tree-sitter loader, the six hook files, the esbuild step that bundles the instrumenter with web-tree-sitter, the three JavaScript grammars, and the tests that prove the library on its own (7). DeepTest keeps its differential test over every fixture project and its own source, the universe, and the Mocha and Playwright driver tests (200).

Three decisions. The hooks read WITNESS_* environment names, not DEEPTEST_*, because a library two tools drive cannot carry one tool's name in its contract; the names are exported as ENV so a tool cannot misspell one, and DeepTest sets both families since its own hooks still read DEEPTEST_*. A bundled extension finds the hook files through the package's hooksDir(), which resolves to dist/hooks once esbuild bundles the package index, where esbuild.mjs copies the package's built hooks beside DeepTest's own; in a checkout the same call resolves into node_modules, so tests and extension take one path. Witness ships its own three grammars for a consumer that has none, but DeepTest keeps pointing the hooks at its own dist, so nothing is loaded twice.

Also in this delivery: every tree now lives under C:\workspace\MikeVan's AI Development Toolkit\ and release.ps1's root, the fixture sync's HelloWorlds path, and the documents' paths follow; release.ps1 aligns five trees, Witness second, and mirrors witness.md into the Witness tree.

The toolkit is also now configured to measure itself. Witness and UntangleIt gain the .vscode/settings.json that complexity and DeepTest already carried, so both extensions know the language, source root, and tests path when either tree is opened, and complexity, Witness, and DeepTest gain the ignore rules UntangleIt already had, so a measuring run leaves the coverage and run records on the machine and only decisions.json and runs.json travel with the code. Without those rules the first run of our own tools on our own trees would have committed its own working files.

The complexity library's walkers were untangled in the same delivery. Five methods sat over the limit of 5 on MBCC: exclusiveKey in python.ts at 31, extractScript in sfc.ts at 25, visit in typescript.ts at 20, exclusiveKey in typescript.ts at 19, and visit in python.ts at 8. Each was one visitor holding every syntax case in a single body, which is what put them over the limit, and it is the wrong shape for a library whose whole pathway is one new language per minor version. Each case is now its own named function, and the suite went from 33 tests to 97 so the cases are covered individually rather than through the visitor. The measures themselves do not change, the suite proves it, and both extensions bundle the rebuilt library.
