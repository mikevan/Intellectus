Angular under Vitest is measured by Witness, on the same plugin the Vitest runner uses. The generated runner config carries the Witness plugin and nothing else, and the builder's own coverage provider is no longer part of the run.

What this retires. 1.0.4 drove Angular through the builder and had to map bundle chunks back to source files through their input source maps, because the builder instruments after it bundles. Witness instruments at transform time, on the source, before any bundling, so the counters are keyed by source file from the start. The chunk-to-source mapping is no longer on this path.

What came out of the run. The --coverage, --coverage-reporters, --coverage-include, and --coverage-exclude flags are gone, and so is the coverage block in the generated runner config. The executable universe of files the builder never transformed now comes from witnessUniverse, the same call Mocha, Playwright, and Vitest use. The environment check no longer demands a pinned @vitest/coverage-istanbul for Angular. Karma still requires its five packages, because that runner has not moved yet.

Why the runner config is now its own function. Neither Angular driver has an end-to-end test: running one would mean carrying the whole Angular toolchain in DeepTest's devDependencies. angularRunnerConfig is pure and tested, so a later refactor cannot quietly drop the plugin or put the coverage provider back, which is how this path would go falsely clean with nothing failing. That test proves what is generated, not that the builder accepts it, and the plan says so plainly rather than leaving the gap implied.

One risk is recorded in the code rather than in anyone's head. The hook still goes in through the CLI's --setup-files, which is the seam the builder documents and 1.0.4 proved, so the builder decides its order against a project's own setup file. The Vitest path controls that order directly and this one cannot. An Angular project with its own setup file under the source root would fail on "reading 'file' of undefined", and the comment above the flag says so.

Also in this delivery. complexity and Witness gain the .gitattributes that DeepTest and UntangleIt already had, which stops a settings file flipping its line endings on every release, six times in one day before this. The Witness README and package description no longer claim one instrument for every JavaScript framework, which is three of eight today; they say what is true and point at docs/witness.md for which runners are on which side. The side panel footer carries the series name through a new PRODUCT_FULL, while PRODUCT stays short so the status bar still reads "DeepTest: checking". DeepTest has Marketplace keywords for the first time.

The plan gains two sections. Phase 8 records CommentIt as a deliberately thin tool for 1.0.17: it says what a method takes, returns, and calls, and states plainly where it cannot know why, because that silence is the argument for the next series. And a debt register lists the work in this slot accepted on thinner evidence than the standard, so it can be collected before the series ends rather than remembered.
